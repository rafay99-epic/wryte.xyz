# New feature directions (Wryte)

Scratchpad for **net-new surfaces**—not incremental polish on existing flows. Add dates or notes as you explore.

**One-line thesis:** the crowded space is “better markdown + AI text.” The open space is **evidence-linked writing**, **release objects across channels**, **governed AI**, and **Wryte as a hub** other tools push context into.

---

## 1. Research-to-draft pipeline

Paste URL, PDF, or transcript → extract claims, quotes, and citations into a **side research panel** linked to specific paragraphs. Emphasis on **structured evidence**, not generic summarization.

## 2. Living sections

Parts of a doc **bind to a query or feed** (e.g. latest GitHub release notes, a calendar block). Refresh or show a **stale** badge. Lightweight “programmable document” on top of markdown.

## 3. Voice layer → structure

Voice memos become **headings, bullets, and open questions** in the outline—not a raw transcript wall. **Outline-first capture.**

## 4. Publish as a product (not only file push)

One doc drives **site + RSS + email draft + social snippets** under a single **release** object with rollback. The artifact is the **release**, not just “push to GitHub.”

## 5. Cowriter with a contract

AI operates under **explicit per-project rules**: allowed edits (tone, length, fact-check flags), forbidden behaviors (e.g. inventing links), and a **visible change log** in the margin. **Governance UX** over more model toggles.

## 6. Reader surface

Share a **reader URL** with highlights, comments, and “suggest edit” flowing back as suggestions—**reader loop** without full real-time co-editing.

## 7. Cross-tool writing context (hub)

Small **API or MCP** so Cursor, Slack, Linear, etc. can drop context into a project (“open doc X with this ticket summary”). Wryte as the **canonical narrative layer** for work elsewhere.

## 8. Time-based writing intelligence

**Sessions** plus **structural feedback** (where you stall, when drafts cluster)—insight over gamification chrome.

## 9. Semantic diff for prose

Show **moved paragraphs and meaning-level changes** when history or GitHub updates—not noisy line diffs. Strong fit if you ship often.

## 10. Multi-surface “modes”

Same project, different shells: **Research** (cards, sources), **Compose** (minimal editor), **Ship** (checklist, previews, channels). **Deliberate context switching** instead of one UI that does everything.
